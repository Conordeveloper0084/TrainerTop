# To'liq audit — 2026-09 (v22 / ZIP v13)

## Topilgan va tuzatilgan (haqiqiy bug)

**Banlangan foydalanuvchining eski kontenti ko'rinishda qolib ketardi.** Ban qo'yish YANGI harakatlarni (post, izoh, sharh, xarid) to'g'ri bloklardi (`getApiUser()` markazlashtirilgan tekshiruvi orqali — bu joyida ishlagan), lekin ban'dan OLDIN yaratilgan kontent hech qayerda filtrlanmagan edi:

1. Bosh sahifadagi "TrainerTop ni baholang" bo'limi — admin tanlab qo'ygan sharh keyin banlansa ham ko'rinaverar edi
2. Trener profilidagi darslik sharhlari
3. Darslikning o'z sharh ro'yxati (`/api/lessons/[id]/reviews`)
4. Post izohlari (`/api/posts/[id]/comments`)

**Tuzatildi**: `platform_review_featured()` SQL funksiyasi endi `is_user_banned()` tekshiradi (mavjud, boshqa joylarda ham ishlatiladigan funksiya); qolgan uchtasi backend'da banlangan ID'larni chiqarib tashlaydi. Baholar/sharhlar/izohlarning o'zi bazada SAQLANIB qoladi (o'chirilmaydi) — faqat ko'rinishdan chiqadi, ban bekor qilinsa yana chiqadi.

## Tekshirilgan va MUAMMO topilmagan joylar

- **Click to'lov integratsiyasi**: imzo tekshiruvi (`timingSafeEqual`), summa serverda hisoblanadi (mijozdan ishonilmaydi), idempotent (ikki marta hisoblamaydi), atomik RPC orqali yoziladi
- **Barcha admin route'lari** `requireAdmin()` chaqiradi — birortasi ham unutilmagan
- **Barcha jadval** RLS yoki REVOKE bilan himoyalangan (brauzerdan to'g'ridan kira olmaydi)
- **Trener/atlet ro'yxatlari, top trenerlar, obunachilar, postlar lentasi** — banlanganlar hammasida to'g'ri chiqarib tashlangan
- **Rol/admin maqomini mijozdan ishongan** birorta route yo'q (hammasi server tomonda `getApiUser`/`requireAdmin` orqali aniqlanadi)
- **Banlash mexanizmi**: yangi harakatlar (post, sharh, xarid, izoh) darhol (∼10 soniya ichida, kesh TTL) bloklanadi — `getApiUser()` markazlashtirilgan tekshiruvi orqali

## Tavsiyalar (bug emas, lekin e'tiborga loyiq)

1. **Banlangan foydalanuvchiga xabar noaniq**: hozir banlangan odam har qanday amalda "Login kerak" (401) ko'radi — texnik jihatdan to'g'ri bloklanadi, lekin sabab tushunarli emas ("nega meni saytdan chiqarib yuborayapti" degan tuyg'u bo'lishi mumkin). Xohlasangiz keyingi safar aniq "Hisobingiz bloklangan: <sabab>" xabari qo'shsak bo'ladi — bu ko'p route'ga tegishli bo'lgani uchun alohida ish sifatida rejalashtirish kerak.
2. **AI Assistant** (`/ai`) hali ham namunaviy (kalit so'z asosidagi) javoblar beradi, haqiqiy OpenAI API emas — bu loyihaning boshidanoq shunday, men buzganim yo'q. Xohlasangiz alohida ishga aylantiramiz.
3. **Darslik videolari** R2'da ochiq (public) URL sifatida saqlanadi — API xaridor bo'lmaganga URL'ni umuman yubormaydi (`stripLessonContent`), lekin haqiqiy xaridor URL'ni boshqa birov bilan ulashsa, texnik jihatdan ochiladi (muddatli/imzoli havola emas). Ko'pchilik shu miqyosdagi platforma uchun bu qabul qilinadigan daraja — to'liq DRM (muddatli havolalar) katta qo'shimcha ish talab qiladi.
